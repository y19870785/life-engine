# 后续开发计划：先完成普通文本体验验证

日期：2026-10-18；代码规划输入 `baa59729babf9ac56a17e02c682de2e3086e3575`。状态：`PROPOSED / NOT_EXECUTION_AUTHORIZATION`。本次授权复盘与文档更新，不授权下面的新 Runtime、Host、模型、渠道或 CI 实施。

Roadmap Stage: 既有 W0/W1 角色试用的验证收敛建议，以及 Soul Continuity 正式主线的准入准备。
Why Now: 角色代码已合并，但完整 T1 仍被依赖环境阻断；应先证明普通文本链可用，避免在未验证的接线层上增加媒体和更复杂记忆。

正式 Soul Continuity 顺序仍为 M0 → M1 → M1.x → M2 → M3…，见 [已审长期计划](SOUL-CONTINUITY-DEVELOPMENT-PLAN.md)。以下 H0—H3 / E1 是本提案的工作包标签，不是新增 SP、正式里程碑或把 Real Delivery 轨重新提前。角色试用验证不等于 Living Real Delivery 集成，不绕过 M1-A 原语门禁。

## 优先级和依赖

| 工作包 | 目标与输出 | 验收 / 停止点 | 建议分工与授权 |
| --- | --- | --- | --- |
| H0：依赖环境与恢复写入方案 | 列出准确 Host revision、导入链、解释器/stdlib、venv/site、.pth/editable finder 的完整加载闭包，以及 cache/install/update-lock/恢复配置的全部读写与子进程；显式处置既有 63 映射回指共享环境的问题，提出源码/依赖版本冻结与隔离方案 | 不依赖字符串路径自称隔离；只读 bind 不等于不可变快照，需验证运行期间上游源文件改变的影响。未知写入、Default Home、共享状态或无法冻结依赖即 `HOST_GAP / STOP` | A 只读设计，B 独立审核；真实 Host 探查若需新访问/副作用，先列明授权范围；不继承旧诊断预算 |

| E1：缩短工程交付等待 | 在不影响 H0 设计的情况下，提出单一状态入口维护、阶段账本/报告自动化与 CI 模块耗时方案 | 先测量再决定分片；完整平台/版本与测试覆盖清单不缩水；本地锁不冒充服务器 Base 原子竞争控制 | 可并行做设计；workflow/工具实现各需独立范围和评审，不混入 Host 修复 PR |

## 下一周期的交付目标

第一目标是一份能执行、能审查的 H0/H1 任务书和隔离方案；只有获得相应授权后，才把完整无模型 T1 作为下一目标。若 T1 未通过，下一周期的有效交付是可复现失败、确定边界和最小修复，而不是对外宣称“基本可用”。不承诺在固定日期完成 Host 接线。

进入 T2 时至少观察：

- 两个独立进程/CLI Session 对应同一目标 Profile/World，开场只出现于新故事。
- 用户原话能追溯到唯一记录；模型候选剧情不冒充外部事实或用户真实经历。
- 不同角色/World 不互读；超窗口时不伪称记得；失败或 PENDING 记录不进入投影。
- 用户纠正可作为最新原话观察，但当前没有结构化纠正/遗忘能力，必须明确告知限制。

上述体验观察不能解锁自动主动联系、图片/语音、工具轮长期经历、Telegram/OpenClaw 扩展或 Full Private RP。只有文本链和隔离证据稳定后，再依据实际缺口另行选择下一个功能。

## 执行方式与收口

沿用主协调规划/汇总、A 单写、B 固定快照审核、C 按需 Host 测试。阶段任务书列明授权 ID/版本、Base/Head、读写对象、允许动作、累计预算、失败修复轮次和停止点；在已有权限内自主完成实施、测试与纠错，超出范围才停。

代码、文档与真实验证分别记录结果；Draft、Ready、Merge、exact main CI 和阶段 DONE 保持分离。当前文档 PR 只交付复盘和提案，不因合并旧代码链而自动取得新阶段权限。建议衡量审核排队时间、CI 运行与等待时间、冲突和重审次数、T1 可复现率及用户介入次数，不以行数/测试数代替产品结果。
