# LE-RESET-01：体验优先的新路线提案

当前裁定与执行权限只见 [STATUS](../STATUS.md)。本提案待独立复核及用户批准后才可用于实施，不改写 M1-P0 协议，不自动启动新阶段。依据：[审计 F01–F08](../reviews/LE-RESET-01-REPOSITORY-AUDIT.md)、[十个体验场景](../reviews/LE-RESET-01-USER-EXPERIENCE-GAP.md)。

## 1. 重新定义交付单位

每个切片交付 **同一版本的可运行包 + 一个稳定入口 + 一张试用卡 + 可导出反馈 + 回退方法**。PR、CI、源码 hash 是可复核基础，不能单独称为体验增量。1–2 周是迭代节奏目标，从获准开工时起计，不承诺外部 Host 能力在期限内出现；期限内失败必须给出可重复反例、准确阻塞与用户能继续使用的上一版。

两轨是规划和预算分配，**不是两条未合并代码线同时开工**。每次只有一个实施切片；另一轨可只读分析。建议约 70% 实施容量给体验闭环、30% 给明确服务于该闭环的可靠性；比例是待批准的分配建议，没有历史工时统计支持。连续两个周期没有用户可试增量，停止扩底座并重审 scope。

## 2. 轨道一：从记忆接续开始

| 切片 / 建议节奏 | 用户得到什么 | 复用 / 最小新增 | 出口及失败处理 |
| --- | --- | --- | --- |
| X2-A，首个 1–2 周 | 一个“退出扮演后仍记得、说清来源”的隔离聊天入口；有记忆/候选/原因卡和重开能力 | 复用 World/Memory、现有回忆录候选、X1 隔离初始化；新增薄聊天编排/UI/诊断，先审查抽取本地候选。详见[X2 合同候选](LE-RESET-01-X2-EXPERIENCE-PLAN.md) | 无模型回放只通过机械门；自然体验须单列模型授权并实际试用。若候选不能在两天准入，缩到已有 Memory 的合成事实读写，不吞入全部 dirty 改动；明确降级能力 |
| X2-B，随后 1–2 周 | “换种说法也能接上、无关时不插话”，以及清楚显示为什么没记住 | 先用 A 的反馈形成保留集；改一个检索/注入因素，比较旧版/新版。纠正普通合成用户陈述复用 supersede；RP 回忆录纠正/局部遗忘仍另审 | 同义漏召回与误召回分别测；质量必须优于冻结基线且安全拒绝不退化。用户还没试 A 时只修阻断，不扩兴趣/关系 |
| X2-C，随后 1–2 周 | 重要约定有一次“可以现在问问吗”的草稿，安静时段不打扰 | 复用 Living followup、tick、quiet/recent/pause；仅本地 outbox 和模拟时间，用户打开试验台时查看 | 四种静默/允许原因、一次草稿和重复拒绝可验；真实 cron/渠道完全另立任务，不因草稿可用解锁 |
| X2-D，反馈支持后再立片 | 一个有来源的小兴趣或暂定判断，几天后继续 | 先人工给三份合成资料、限一步选择/问题/改观；不后台联网、不建 Agent 社交网络 | 能看出新证据如何改变判断；若只是角色措辞无持续状态，判未达标；U04/U05 不由生活作息表替代 |

图片、语音和多 Agent 不是同一周期并做的附赠。只有用户对文本闭环的反馈指向明确需求，再选择 U07 或 U08 中一项；先局部真实生成/人工质量，再谈渠道。不能因某个 Host 阻塞就自动改做另一个大子系统。

## 3. 轨道二：长期可靠性，按依赖推进

| 层次 | 可以保留的工作 | 依赖 / 需要明确决定 |
| --- | --- | --- |
| 发布与诊断可信 | commit/源清单→测试→包→运行版本→反馈绑定；错误不吞成“无记忆” | 直接支撑 X2；缓存摘要缺口先复核，不自动在本轮修复 |
| 身份与 lineage | 保留 M1-A 同身份绕过/整体回滚反例；评估独占 authority 与备份域的现实成本 | 正式 M1→M1.x 顺序保留。若单机威胁模型无法提供 nonrollback 域，应提交边界/架构决策，不无限微修，不声称 X2 是正式 continuation |
| 记忆演化与关系 | 来源、候选、纠正、删除、派生失效；之后 PersonRef/关系/自传 | 正式 M2 仍依赖原门禁；X2 只复用既有机制做合成试验，不偷渡正式 writer 或关系真源 |
| 恢复证明与迁移 | 继续区分数据库恢复、continuation、执行权、外部发送真相 | E0 进程模拟不代表 E1/E2/E3；OS/VM/断电及生产迁移各自授权 |
| 云/本地混合推理 | 先为同一脱敏 fixture 比较准确性/延迟/成本；路由是执行层选择，模型不成为 Soul | 需具体 provider/本地模型、数据可出域范围、硬预算与凭据引用授权；目前只规划，不下载、不读密钥、不调用 |
| 真实 Host /渠道 | 复用 W1 栈与 HLV 已有证据，按版本固定重新验证 | X2 用户证据稳定后再评估最短产品入口；W1 依赖闭包仍可单独排队，Full Private RP 与真实发送安全门不解除 |

## 4. 复用、修补、延后与暂停

- **直接复用：**WorldScope/Session、Memory candidate/accept/supersede/delete、SQLite/代次围栏、X1 隔离创建、Living 静默原因、既有试用卡格式。继续纯标准库。
- **关键修补：**消费链、安装版本身份、阶段诊断、候选管理入口、会话结束可观察性。provider 本地候选先缩小审查范围，不能把所有未提交代码统称已审资产。
- **可延后：**向量数据库、全量语义记忆整理、关系数值模型、大资产库、完整故事编辑器、云本地自动路由、统一多 Host 适配。
- **暂停扩张：**无人使用前继续堆生活字段；以更多局部安全测试代替新体验；用放宽 subprocess allowlist 追求一次 Host 成功；无限嵌套依赖 PR；没有新官方能力证据的 Full Private RP 重试。

## 5. 与既有规划的关系

这是对旧“X2=可信底座收口”以及“先完成 W1 才有体验”的**产品优先级修订提案**。正式 M1/M1.x/Memory Evolution 架构依赖不在此解除。X2 永远使用新的可丢弃合成实例，标明未经正式 continuity proof；不导入真实 Soul 数据，不声称普通重开已证明合法 continuation。

旧 CODEX-STAGE-AUTONOMY、Soul 计划及 #62 原件保留为证据。复核应确认新提案的隔离边界足以允许体验轨先行；若认定必须修改既有架构合同，应先完成该明确变更，不能在实现时默默绕过。当前没有为回忆录遗忘另造 source/key 的授权。

## 6. 下一次授权应决定的最少事项

1. 是否批准 X2-A 的范围、一个实施分支和 1–2 周体验节奏；独立复核谁来做。批准规划不等于批准生产。
2. 先交离线机械入口，还是同时批准**独立模型子合同**，让首版即可评估自然接话。推荐后一种，但必须先固定模型目标、凭据引用、合成数据与硬请求预算；本 PR 不替用户作出该许可。
3. 默认全新 X2 fixture、单用户、单进程、无渠道。以后是否把同样体验接入日常小雪，必须先证明实际 Host/Profile/版本关系，不能把 dongxue 的记录直接算给她。

试用结束只需反馈“我想保留的一点、最不自然的一句、下一次最想改的一件事”。工程定位由代理完成，不让用户再充当每步执行的调度器。
