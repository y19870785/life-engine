# LE-RESET-01：X2 隔离体验试验台方案

执行状态与权限见 [STATUS](../STATUS.md)。本文是可供批准的具体范围，**不是已存在的工具说明**。目前可运行入口只有下文 A 段；B 段 X2 命令与页面均需实施。依据：[能力矩阵](../reviews/LE-RESET-01-CAPABILITY-EVIDENCE-MATRIX.md)、[路线](LE-RESET-01-REVISED-ROADMAP.md)。

PR #64 Review 后的具体实施口径以[X2-A L1提案](LE-RESET-01-X2-A-L1-IMPLEMENTATION-PROPOSAL.md)为准：只复用三文件最小Core闭包与纯选择函数，排除整套provider/自动flush/迁移。真实模型先采用[六请求独立冒烟合同](LE-RESET-01-X2-A-MODEL-TRIAL-CONTRACT.md)，下文28请求仅保留为未授权的后续持续观察建议；不是本轮最小预算。

## 用户价值与首个垂直切片

**X2-A：退出一次扮演，下次打开仍能接上，并说明那是扮演。** 用户只需一个入口，输入合成经历，看到“候选→接受→可召回”，关闭窗口后再来；查不到时能分清没记录、没接受、没命中或服务不可用。角色名只是可换显示名；不复制小雪生产 Persona、聊天历史或身份。

首版只解决 U09 和 U06 的记忆解释部分，加 U03 的普通跨进程读回。U01 的全面纠正、局部遗忘、兴趣演化和真实主动跟进不混入此片。若只能复用 main 的普通 Memory 而回忆录候选未获准入，降级版只交合成用户陈述的记录/接受/读回，不宣称已实现扮演回忆。

## 一条薄消费链，复用现有 Core

```text
本机浏览器聊天 / 显式结束会话
  → 单用户会话控制器（同一 fixture 同时只开一个进程）
  → World / Memory 原有 API（candidate / accept / query）
  → 回忆录候选服务（仅在抽取审查通过后复用）
  → 有来源且有预算的上下文包
  → 离线回放端口 或 另行获准的模型端口
  → 用户回答 + 可展开的记忆依据卡
```

不新造数据库、记忆权限、通用 Agent Runtime 或消息调度器。薄编排不可自签 authority、伪造受信 PromptSnapshot 或改写 Bridge 语义。正式 Prompt P1/模板变更不在本片；独立上下文包必须标为 X2 试验输入，而非已升级的正式 Prompt Runtime。若现有安全 API 不能组合，停止相应操作并提出具体设计问题。

### 候选文件范围（批准实施后）

- `tools/experience_x2.py`：单命令创建/启动/状态/导出/停止，静态页面和标准库 loopback server。可以按审查意见拆薄模块，但不能变成另一个 Runtime。
- `examples/x2/`：原创合成卡片与事件；不包含人物隐私或生产设定。
- `tests/test_experience_x2*.py`：真实子进程重开、候选隔离、授权/失败/禁网/导出边界；复用现有 Core fixture。
- `docs/trials/X2-A.md`：用户操作和已知能力边界；状态仅维护 `docs/STATUS.md`。
- 本机候选 `roleplay_recall.py`、provider 的复用必须逐文件明确 diff、hash、独立审核及必要回归；不默认批准改 `domain.py`、Memory 写门或所有未提交文件。需要改安全断言、Schema 或持久协议立即停。

建议开工前两天完成候选准入和最小提取。来源级删除、Unicode 匹配与缓存摘要等已知候选风险须先确认对该切片是否可达；不可达需给调用证据，可达且影响安全/包身份则先单线收口，不带病发布。两轮同因未收敛便缩小范围或停止，不能无限拆可靠性任务冒充体验。

## 单命令、聊天页和每日使用方式

拟提供的首次启动命令（**尚不可运行**）：

```powershell
py -3.12 -B -X utf8 tools/experience_x2.py start --new --offline
```

启动器只在系统临时根创建带标记的全新 fixture，校验非链接路径；监听随机 `127.0.0.1` 端口而非 `0.0.0.0`。拒绝指定生产 Home/store；无默认 `~/.hermes`、无环境猜测目标、无 .env 扫描。返回带一次性本地会话口令的 URL，校验 Origin/Host、CSRF token、请求长度和方法；无 CORS 放开、远程资源、文件浏览或任意命令端点。口令不进入导出与常规日志。离线模式拒绝模型端口构造和非 loopback 网络。

聊天页只保留：模式标识、聊天框、“结束本次扮演”、“查看/接受候选”、“记忆依据”和“反馈”。运行模式显示“离线回放”或“模型试用”，离线不产生冒充自然对话的智能回答。技术 ID/hash 放到可展开诊断，不要求用户配置数据库字段。

再次启动拟使用 `start --fixture <首次生成的试验ID> --offline`，ID 必须由受管索引映射到原临时目录，不接受任意路径。记录与事件沿用同一 fixture，不自动重建空实例掩盖丢失。CLI 负责停止和连接既有进程，不双开同 store；不创建后台服务或定时任务。用户退出后可次日手动启动。**这些是实现合同候选，不是现有能力。**

### 模型体验子合同（必须另行明确批准）

推荐在首版同一迭代内另行批准隔离模型试用，否则只能交机械/交互入口，不能承诺用户感受到自然接话。最小合同应绑定：

| 项目 | 待批准的具体边界 |
| --- | --- |
| 对象 | 已审 X2 commit/包 manifest、唯一新 fixture、唯一模型端点与模型名；不接生产 Hermes/Gateway |
| 数据 | 仅本片合成事件和用户明确写入 X2 的合成输入；禁止读取生产历史、文件或系统 Persona |
| 凭据 | 用户指定的最小凭据引用；秘密不进 repo、日志、导出或页面；没有引用就禁用，代理不搜索密钥 |
| 建议预算 | 七天内最多 28 次真实 provider 请求，含失败与重试；最多 7 次会话，每次最多 4 请求；无自动重试。先两会话做冒烟，其余额度用于持续观察；另锁定 token/费用上限，缺上限不调用 |
| 硬计数 | 请求前持久预留，重启不归零，未知结果仍计数；无工具/媒体/消息渠道；服务端不把按钮点击重复发成两请求 |
| 输出语义 | 模型回复为候选；新增事实不能未经接受写成用户事实；已知扮演始终 FICTIONAL / FICTIONAL_SHARED_EXPERIENCE |
| 停止 | 越 scope、未知请求计数、秘密或跨 World 泄漏、包摘要变化即关模型端口；不因试验失败自动切另一 provider |

28 次只是可审提议，不是本 Issue 的调用许可。到期或额度耗尽后禁用模型，离线仍可读记录，用户试用也不自动续额。真实 Host 接入另有合同，不用“本机端口”偷换为无网络/无真实模型。

## 可见证据、导出、回退

每轮只记录合成运行所需的阶段事实：版本/fixture/session、输入事件摘要、候选 ID/接受状态、检索命中 ID/未命中原因、注入字节预算、输出模式、固定失败码和模型请求计数。默认诊断不含正文；用户可在自己打开的试验页查看已接受的合成记忆和来源。记录失败应可见，不能伪装成“没有相关记忆”。后台堆栈与敏感参数不进页面。

导出默认包含脱敏运行身份、场景判定和反馈，不包含 token、完整提示、正文、绝对个人路径或生产数据。需要正文时只允许用户显式选择本 fixture 合成条目并预览；原始 Owner 查询不能变成任意数据导出入口。源码不改产品 Schema；诊断是 fixture 外围记录，不是新的 Soul 真源。

回退通过停用当前包并保留原 fixture、不再写入来完成；只在完全兼容时允许旧包读取，未知布局拒绝。旧数据、删除控制、cursor 不重置；不恢复已忘内容、不自动重放、不回滚生产。创建全新 fixture 可以继续演示，但不能说故障 store 已恢复。删除 fixture 只允许验证过的受管临时目标和显式操作，测试不以生产删除为步骤。

## 开发与体验验收

| 门 | 必须实际观察 | 不能替代 |
| --- | --- | --- |
| 离线机械门 | 全新实例→候选不召回→显式接受→关闭/新进程召回；其他 World 拒绝；失败固定码；重复接受无重复 | 不替代模型自然度、Host 和正式 continuity proof |
| 本地 UI 门 | 一条启动命令、唯一聊天入口、停止/重开、版本可见、反馈可导出；坏 token/origin 与任意路径拒绝 | 不因出现聊天框就称模型已连接 |
| 模型观察门 | 获准后实跑明确追问、自然提及、无关主题、未知细节；分别保存输入版本、检索/注入结果与脱敏回答 | 不用模型自述“我记得”证明底层写入 |
| 用户持续门 | 用户至少三次不同会话亲测，建议一周；记录记得/不添事实/不打扰/有用及未观察项 | 三次是首轮观察建议，不能推断长期稳定性或伪造满意度 |

错误世界、现实性升级、候选泄漏、未知预算继续调用是硬失败。自然度未达标优先修当前闭环，不开始语音/多 Agent。全量测试仍按现有要求运行，不以增加同构断言代替实际新进程/真实 wrapper 场景。

## 三十分钟试用脚本

### A. 现在可跑：main 的离线机械基线（0–15 分钟）

从本 PR/固定 main 的仓库根目录运行，Python 3.12。只创建系统临时合成实例；本轮已按这些操作取得实际结果。不要执行 START-HERE 的安装/Gateway 步骤。

```powershell
py -3.12 -B -X utf8 examples/experience_x1.py init
# 将输出 sandbox 的完整路径粘贴到下一行，勿填现有 Host 或生产目录
$x1 = 'init 输出的 sandbox 路径'
py -3.12 -B -X utf8 examples/experience_x1.py day0 --sandbox $x1
py -3.12 -B -X utf8 examples/experience_x1.py day0 --accept --sandbox $x1
```

0–5 分钟：第一条 day0 应为 `NOT_ACCEPTED` 且无 accepted_memory；第二条为 `ACCEPTED`。输入是脚本固定的合成面试文本，不是任意聊天。

5–10 分钟：关闭终端再打开，回到仓库根，重设同一个 `$x1`，执行：

```powershell
py -3.12 -B -X utf8 examples/experience_x1.py day1 --sandbox $x1
py -3.12 -B -X utf8 examples/experience_x1.py status --sandbox $x1
py -3.12 -B -X utf8 examples/experience_x1.py isolation-check --sandbox $x1
```

应看到原合成记忆、来源/World，隔离检查为 `ISOLATED`；活动为合成时钟推断。每次 Python 命令都是新进程。本轮实际 day1 的 current_activity 为 `UNKNOWN`，不是自然日常生活通过。

10–15 分钟：只对本次临时 fixture 遗忘，再新进程查：

```powershell
py -3.12 -B -X utf8 examples/experience_x1.py forget --sandbox $x1
py -3.12 -B -X utf8 examples/experience_x1.py day1 --sandbox $x1
```

应看到 `FORGOTTEN`、`normal_query=[]`，之后 memory 仍为空。所有 model 字段应为 `MODEL_NOT_CONNECTED`。这段不能观察真实回答、自动日常、小雪渠道、W1 或正式同一 Soul 证明。保留临时 fixture 供反馈，不要求删除任何数据。

### B. 仍需实施：X2 聊天闭环（15–30 分钟）

**目前不要运行拟议 X2 命令；不存在该工具。** 开工批准并交付后，15–18 分钟用上面的单命令打开试验页，确认“离线回放/模型试用”与包版本。18–22 分钟输入合成扮演“我们在蓝灯书店找到地图”，结束扮演，预览候选，明确接受。22–26 分钟停止再打开同一 fixture，问“蓝灯书店后来怎样了？”并查看对应来源；26–28 分钟换无关问题和从未提供的店主姓名；28–30 分钟导出三条观察及一个最想改善的问题。

没有模型授权就只看阶段证据，回答自然度写 `未观察`。若有获准模型实跑，按“记得、知道是扮演、不添事实、不打扰、有用”逐项评价。遗忘与纠正不得调用尚未审定的 RP 来源改写；先用候选拒绝/正常可见性解释限制。
